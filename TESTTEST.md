regression from this session's feature work, but only surfaced by it):** the `unprivileged_role`
fixture in `tests/integration/test_migrations_and_rls.py` built its non-superuser connection URL
with a hard-coded `PG_URL.replace("://labellens:labellens@", ...)`, matching only the
`infra/docker-compose.yml` dev credential convention. Against a test container provisioned with
different credentials (e.g. `postgres:labellens`), `.replace()` silently no-ops, and the "unprivileged"

**Four genuine bugs found and fixed by this verification - the reason it was worth doing at all,
not a formality:**

1. **Dockerfile: `paddleocr` needs `libgl1`/`libglib2.0-0`.** This project's own dependency is

   `opencv-contrib-python` transitively regardless - confirmed by actually building
   `python:3.12-slim` + `.[dev,ocr]` and hitting `ImportError: libGL.so.1` on a plain `python -c
   "import paddleocr"`. Fixed by adding both packages to the Dockerfile's `apt-get install` list.
   Rebuilt and reverified: the image now imports `paddleocr` and the full app together cleanly.
2. **A standalone Arq worker process never imported `app.db.models`.** `app.main` is normally what
   pulls in every mapped table so SQLAlchemy can resolve cross-table foreign keys; a worker started
   via `arq app.analysis.worker.WorkerSettings` never imports `app.main` at all. The very first real
   flush touching `analyses` raised `NoReferencedTableError` resolving `ruleset_version_id`'s FK to
   `rulesets`, a table that process had genuinely never heard of. **Invisible to the entire test
   suite**, because `tests/conftest.py` always imports the full app graph via `app.main` regardless
   of what the test under execution touches - exactly the class of gap only running a real,
   separately-invoked process catches. Fixed with a top-level `from app.db import models as
   _models` import in `app/analysis/worker.py` itself, documented in `_on_startup`'s own docstring.
3. **`dlq.replay_dead_letter`'s router endpoint never enqueued the replayed analysis's first job.**
   Found live: two dead-lettered extractions (real `503` capacity errors from Gemini, not a code
   defect - P5-T3's retry-then-dead-letter machinery worked exactly as designed) were replayed
   successfully but sat in `queued` forever, unlike `submit_analysis`, which now starts a genuinely
   new analysis automatically. Fixed in `app/analysis/router.py::replay_dead_letter` to enqueue too,
   with a regression test (`test_analysis_dlq_router.py::test_replay_enqueues_the_new_analysiss_first_job`).
4. **A pre-existing dedup/rasterization bug (P2-T4-era code, not touched today) - found, not yet
